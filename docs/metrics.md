# Operating metrics

Numbers below come from the production D1 database (`understory`), read with the SELECT-only queries in [`scripts/metrics.sql`](../scripts/metrics.sql). Every statement reported `changes: 0` and `changed_db: false`.

Snapshot: 2026-11-21 02:19 UTC. Data window: 2026-10-20 to 2026-11-21.

Re-run:

```sh
npx wrangler d1 execute understory --remote --config wrangler.jsonc --json --command="$(cat scripts/metrics.sql)"
```

Use `--command=` with the equals sign: the file starts with a `--` comment, which Wrangler otherwise parses as a flag.

How to read the table:

- "Unknown citation id": the model cited excerpt block ids (`b1`, `b79`) instead of source ids (`s1`). The repair strips unknown cites, so these jobs still failed on another schema issue. `last_error` is cut at 700 characters and lists the pre-repair issues, so the remaining issue is often hidden.
- All 12 "Workers AI error" rows are `5028: @cf/qwen/qwen3-30b-a3b-fp8 was deprecated on 2026-11-20`. The pipeline model needs replacing before generation can resume.

Latency for finished jobs, `created_at` to final `updated_at` (queue wait, retries, and processing):

| Kind | Jobs | p50 | p95 | max | mean |

The generate tail is backlog, not model time. On the 6 days the budget filled, remaining generate jobs were deferred to the next UTC midnight, and a deferred job keeps its original `created_at`.

## Limits of these numbers

- Counts are rows still in D1. `npm run storage:retention` previews deletion of old `jobs` and `explanation_revisions` rows. If it is ever applied, re-run the queries before quoting totals.
- Pass rates are per generate job. An article that failed and was regenerated counts once per job.
- Percentiles are nearest-rank over finished (`done`) jobs only.
